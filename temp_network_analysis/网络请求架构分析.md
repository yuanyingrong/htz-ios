# iOS项目网络请求架构与专辑拉取流程分析

## 1. 网络请求基础架构

### 1.1 核心网络框架
项目使用了 **Moya + Alamofire** 的网络架构组合：
- **Moya**: 作为网络抽象层，提供类型安全的网络请求接口
- **Alamofire**: 作为底层网络实现，处理HTTP请求
- **SwiftyJSON**: 用于JSON数据解析

### 1.2 网络管理核心类
- **HTZNetWorkManager.swift**: 网络请求管理的核心类
  - 提供统一的网络请求方法：`NetWorkRequest()`
  - 实现了请求拦截、日志记录、错误处理等功能
  - 内置mock数据机制，当网络请求失败时返回模拟数据
  - 支持网络连通性检测

### 1.3 配置文件
- **MoyaConfig.swift**: 定义了基础URL和常量
  - API基础地址：`http://39.105.174.143:9100/`
  - 下载服务器地址：`http://39.105.174.143:9400/`
  - OSS资源地址：`https://htz-sutra.oss-cn-shanghai.aliyuncs.com/`

### 1.4 请求流程
1. 通过`NetWorkRequest()`发起请求
2. Moya将请求转换为Alamofire请求
3. 处理响应数据，使用SwiftyJSON解析
4. 错误处理：网络失败时返回mock数据

## 2. 专辑相关API接口

### 2.1 专辑API定义
在`API.swift`中定义了专辑相关的API接口：
```swift
case albums // 获取所有专辑
case xingfuneixinchan // 性芬内省禅专辑
case jingxinyangsheng // 净心养生专辑
case mixinxiaoshipin // 密信小视频专辑
case sutras(page_index: NSInteger, page_size: NSInteger) // 分页获取经典列表
case items(sutra_id: String, page_index: NSInteger, page_size: NSInteger) // 获取专辑内容
```

### 2.2 请求路径和参数
- 专辑数据使用静态JSON文件存储在服务器上
- 例如：`albums.json`, `xingfuneixinchan/xingfuneixinchan.json`
- 支持分页加载，通过`page_index`和`page_size`参数控制

## 3. 数据模型和解析逻辑

### 3.1 核心数据模型
1. **HTZSutraInfoModel**: 专辑信息模型
   - 包含专辑ID、名称、封面、描述等基本信息
   - 使用HandyJSON实现自动序列化/反序列化

2. **HTZSutraItemModel**: 专辑内容项模型
   - 包含音频ID、标题、时长等信息
   - 支持音频和视频两种类型

3. **HTZMusicModel**: 音频播放模型
   - 继承NSObject，实现HandyJSON和NSCoding协议
   - 包含播放相关属性：音频链接、歌词链接、封面等
   - 支持本地缓存和下载状态管理

### 3.2 数据解析流程
1. 服务器返回JSON数据
2. 使用SwiftyJSON解析为JSON对象
3. 通过HandyJSON的`deserialize()`方法转换为模型对象
4. 处理图片URL，添加OSS前缀

## 4. 专辑拉取的完整调用链路

### 4.1 专辑列表获取流程
```
HTZAlbumViewController.viewDidLoad() 
→ configData() 
→ albumViewModel.requestData() 
→ NetWorkRequest(API.sutras()) 
→ HTZNetWorkManager处理请求 
→ 返回JSON数据 
→ HTZAlbumViewModel解析数据 
→ 更新UI展示
```

### 4.2 专辑详情获取流程
```
HTZAlbumListViewController.viewDidLoad() 
→ sutraInfoModel.didSet触发 
→ requestData() 
→ albumListViewModel.requestData() 
→ NetWorkRequest(API.items()) 
→ HTZNetWorkManager处理请求 
→ 返回JSON数据 
→ HTZAlbumListViewModel解析数据并转换为HTZMusicModel 
→ 更新TableView展示
```

### 4.3 特定专辑加载流程
对于特定专辑(如xingfuneixinchan)：
```
HTZAlbumListViewController.requestData() 
→ albumListViewModel.requestData(index:isPullDown:) 
→ NetWorkRequest(API.xingfuneixinchan) 
→ 获取静态JSON数据 
→ 解析为HTZSutraItemModel数组 
→ 转换为HTZMusicModel用于播放
```

## 5. 网络层特点

1. **容错机制**：当网络请求失败时，自动返回模拟数据，保证应用正常运行
2. **资源管理**：图片资源使用OSS存储，支持本地缓存
3. **下载功能**：集成下载管理器，支持音频离线缓存
4. **日志记录**：完整的网络请求日志，便于调试
5. **连通性检测**：内置网络状态检测，可根据网络状态调整行为

## 6. 数据流向总结

1. 用户进入专辑页面 → 触发专辑列表请求
2. 选择特定专辑 → 请求专辑详情内容
3. 转换数据模型 → 渲染UI界面
4. 用户点击播放 → 初始化播放器并加载音频资源
